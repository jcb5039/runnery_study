# 15주 — 동기화 흐름을 직접 정리하기

먼저 [15주 실습](../week15/README.md)을 실행하세요. Map과 List는 서버·로컬·대기열을 흉내 낸 메모리 값이에요.

```text
오프라인에서 저장
  → 로컬 기록 보관
  → 전송할 ID 보관
  → 서버 전송 시도
      ├─ 실패 → 작업 유지 → 온라인 복귀 뒤 재시도
      └─ 성공 → 완료한 작업 제거
```

7일 실습에서 각 화살표에 해당하는 코드 줄을 찾고 아래 표를 직접 작성하세요.

| 사건 | 로컬 기록 | 서버 기록 | 대기 작업 | 다음에 할 일 |
| --- | --- | --- | --- | --- |
| 오프라인 저장 직후 | | | | |
| 첫 전송 실패 | | | | |
| 온라인 복귀 후 성공 | | | | |
| 성공 응답을 놓쳐 같은 ID 재전송 | | | | |
| 로컬 삭제 후 아직 서버에 전달 못함 | | | | |

확인할 질문:

- 로컬 기록과 pending이 메모리에만 있으면 앱이 꺼질 때 무엇을 잃나요?
- 서버가 저장했는데 응답을 받지 못했다면 재전송이 중복 기록을 만들 수 있나요?
- 삭제한 ID를 잊고 서버 목록을 받으면 어떤 일이 생기나요?
- 두 기기에서 같은 기록을 바꿨을 때 단순 Map 대입만으로 충분한가요?

[Runnery 코드 지도](../project-map.md)의 `RecordSync`를 읽고 `_push`, `_pull`, 재시도와 삭제 처리 위치를 표시하세요. 새로 알게 된 조건은 위 그림 옆에 추가해요.
